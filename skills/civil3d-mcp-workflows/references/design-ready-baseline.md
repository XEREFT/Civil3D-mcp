# Design-ready BASE sheet - what the design engineer needs (design audit 2026-10-25)

Source: reverse engineering of two finished designer sets (Villa One "how it should look" `C-300_GUIA_COMO_DEBE_QUEDAR.dwg`; Goulds Design 2026-07-31 / 08-03 + the dated
folders of Goulds) against our BASE deliverables. Both references were drawn by a human, so every rule below says whether it is **COPY** (the designer is right)
or **FIX** (the designer's file has an error; we do the right thing instead). Check any BASE with `node scripts/design-ready-audit.mjs --dir "<base folder>"`
(ids DR-01..DR-13 below); tools that fix each gap are named in the last column.

## Procedure (new BASE or rebuild)
1. `new-project.mjs` / `poc-extract.mjs --project` -> subject, folios, connections.
2. Take the NEWEST client X-TOPO/X-UTIL/X-ARCH (not a designer folder). If the survey has no centerline near the lot: `centerlines-extract.mjs --dump <dump> --window ... --save <dir>`.
3. Set `site.pocPoints` (connection MH / tie-in) and, if known, `site.viewport`.
4. Put the POC-governing as-built in `_reports/asbuilt.json`; run `asbuilt-survey-merge.mjs --asbuilt ... --dump <X-TOPO dump> --window ...`.
5. `fase1-from-scratch.mjs --dir ... --dwg "<Name> @xereft base.dwg" --template _template.dwg --rebuild` (north arrow, gray look included).
6. `design-ready-audit.mjs --dir ...` must show 0 FAIL; every WARN is either fixed or explained in project.json `decisions`.
7. `package-base.mjs`.

## Source precedence override (user, 2026-10-26)
Default is survey-first (designer convention). When the user says "follow the as-built" for a manhole, set `preferAsBuilt: true` on it in `asbuilt.json`:
the label prints the as-built values, the survey ones stay in `surveyIgnored`, and `asbuilt-survey-merge.mjs` keeps the choice on reruns. Applied to Goulds MH#1 only.
Map as-built manholes to the drawn ones by position along the run and by the NUMBER of pipes (Goulds: the 2-pipe surveyed MH is MH#14-A, not the 3-pipe MH#14), never by order of appearance.

## Labeling style learned from the designer sheets (user request 2026-10-26, applied to Seindestein)
Counted on the plan view of Villa One "how it should look" and Goulds 08-03 (`design-gap-diff.mjs --texts`):
* **R/W is NOT re-labeled along the street.** The plan prints the survey's own R/W dimension texts plus the building-frontage ones; "EXIST RW" MLeaders appear only on the profile views. Our `EXIST R/W` / `EOP` grid (`c300-road-labels.mjs`) already goes beyond the designer; do not add more.
* **U.E. is one label per easement**, not one per corner: a single `EXIST 5' U.E.` MLeader with its arrow on the easement line, next to two `5.00'` dims (`c300-easement.mjs`, needs `project.json site.ue` = lot line + width confirmed by the user/plat). No easement in the survey or the PA data = nothing to draw (Seindestein: none; never invent one).
* **Every structure the survey measured is labeled** (Villa/Goulds DR-12/DR-13): `EXIST STORM CB RIM: 9.34 (TO REMAIN)` on the designer sheet; Seindestein uses the MDWASD form `EXIST. STORM C.B. RIM: 9.22'` (no "(TO REMAIN)": that phrase is a design decision, Fase 1 only documents what exists; it stays only on the firm recipe labels for mains and hydrants with an as-built source) (A 10.0: C.B. = Catch Basin; A.7 symbol = square with a cross-hatched grid, the "rejilla"; note "C.B. #" there means Core Boring #); manholes `EXIST. SAN MH / RIM / INV (dir)`; storm manholes `EXIST. STORM SEWER MH` (name from the MDWASD legend A.7 / code list: MHSS = Storm Sewer Manhole, MHSA = Sanitary, CBA = Catch Basin, plus A 10.0 abbreviations EXIST., MH.; "S.S." is spelled out because it also reads as sanitary sewer; NO designer sheet labels a storm MH, so this name comes from the MDWASD base, not from Villa/Goulds). The FormTech survey keeps those values on the layer `INVERTS & MANHOLES` (frozen in the host), so the sheet shows the symbols without text until `node scripts/c300-survey-structures.mjs --dump X-TOPO_dump.txt --center <frame centre> --twist <rad> --place place.json` adds the labels (only structures inside the C-300 frame; `--place` = hand-placed text offsets in sheet axes). Same MLeader recipe as the utility labels (C-ANNO, Formtech-1.0, 1.4 ft, gray, 26-character wrap).
* Placement: text in an empty pocket (between the R/W line and the pavement edge, or beyond the lot), never over street names, stations or dims, and never clipped by the viewport edge (a text left of its arrow extends leftwards: check the PDF crop). View the PDF after every placement.
* **Sheet frame vs the connection point** (user 2026-10-26): the frame is 500 ft at 1"=20' (labels are not annotative, another scale would shrink them), so when the nearest sanitary MH of the POC / survey is outside it, move the main viewport (`setViewportTwist` with new centre) until that MH is inside; the lot must stay inside with margin and labels must not be clipped. Seindestein: centre 893305.18, 497887; SW 74th ST and ALIGNMENT START left the frame. POC, as-builts and title-block data (AGR, project no., GPD) are the client's / design engineer's: Fase 1 only cleans and carries the data. Vertical datum: use the sheet notes (NGVD29) when the survey states none.
* **R/W at corners**: good practice is one R/W label per corner / change of direction; the survey's own `R/W` texts already do it at the intersections in frame, so no extra labels were added.
* **Storm pipes**: the survey has no storm linework; never draw inferred pipes. The C-300 PROJECT SPECIFIC NOTES carry a bullet `EXISTING STORM SEWER PIPES CONNECT THE SURVEYED STRUCTURES SHOWN (RIM AND INVERTS PER SURVEY). CONTRACTOR TO FIELD VERIFY SIZE, MATERIAL, LOCATION AND INV.` (MText edit with `updateTextContent`, keep the paragraph codes).
* **Not needed for design (user 2026-10-26)**: `GRASS MEDIAN` and `ASPHALT WALKWAY` callouts and the walkway outline lines are hidden (`topo-hide-pavement-labels.mjs` group `landscape`, default on; the outline lines go in `--also <handles>`: find them with the PAVEM entities next to the texts, keep the road edges). `--place` accepts `"wrap": n` per structure.
* **White symbols**: the SMH (S in a circle) definition holds ByLayer entities on layer 0, so a colour on the INSERT does not reach them and the gray layer override wins; `topo-white-blocks.mjs` recolors the definition entities as well. Symbols drawn as a bare CIRCLE (not a block: Villa one / Goulds `SYMBOLS` r 1.05) are caught with `--circles SYMBOLS:1.05`, which sets WHITECIRC on them in the X-TOPO copy.
* **White labels in a project that has no R-W lines** (user 2026-10-26, Villa one / Goulds): run `scripts/labels-white.ps1 -Doc "<name>*" -Save` on the open drawing: layer C-ANNO colour 7, every MLeader entity colour 7 and its TEXT colour white (DXF 90/92: -1023410168 ACI 8 -> -1023410169 ACI 7, only reachable with entmod through SendCommand, not over COM). R/W marks, R/W line extension and median/walkway hiding do not apply there (no `R-W` lines in the survey; the sheets already carry orthogonal EXIST R/W / EOP rows).
* **R/W at every R/W corner, all white** (user 2026-10-26): add a white `R/W` MLeader (C-ANNO, height 2.4, colour 7, text rotation 2*pi - twist) on each leg of every R/W corner (turn of the `R-W` lines; Seindestein: the two T-corners with SW 76th ST, corners at 893298.54,497673.38 and 893348.48,497675.85). Legs that already carry a survey `R/W` mark within ~35 ft are not repeated; the others get one ~6-14 ft from the corner, arrow on the line, text in the empty pocket (check the PDF: the lower corner collided with the C.B. leader and the SAN MH label until it sat 6 ft from the corner and 6.5 ft off the line). The survey's own R/W marks become white with `node scripts/topo-white-rw.mjs --topo X-TOPO.dwg --out copy.dwg` + `xref-reload.ps1` (explicit colour 7 on the MTEXT "R/W" and its LEADER). Our labels are white: MLeaders colorIndex 7 and layer C-ANNO colour 7 (open drawing: set `.Color = 7` over COM on the existing ones; the standard `existingUtilityLeader.colorIndex` was 8).
* **R/W marks, one uniform set (user 2026-10-26, four rounds: "no alineados, uno blanco y otro gris" -> "no entiendo por que quitaste las RW" -> "no hay ninguna en estas cuatro esquinas" -> "geometricamente estetica")**: command `/rw-marks` = `node scripts/c300-rw-apply.mjs --dump X-TOPO_dump.txt --twist <rad> --frame <sheet frame x0,y0,x1,y1> --box <whole plan> --extend-config streets.json`: erases every host MLeader whose text is exactly `R/W`, regenerates, creates, saves (`--dry-run` only reports). One-off per project: hide ALL the survey's own R/W marks (`node scripts/topo-white-rw.mjs --topo X-TOPO.dwg --hide --out copy.dwg` + `xref-reload.ps1 ... -Freeze "X-TOPO|HIDE-PAVEMENT-LABELS"`). Rule (`c300-rw-marks.mjs`): a mark 14 ft from every R/W corner on each leg and then at equal ~125 ft along every run, over the WHOLE plan (model space too: the user looks at the corners of every intersection, not only the sheet), including the extension lines of `c300-rw-extend.mjs` (`--extra`). **Geometry = EOP signature**: leader strictly orthogonal on the sheet axes (vertical for a line running across the sheet, horizontal for one running up it), 8 ft long, text beyond the landing (right of a vertical leader), white. Calibration measured on Formtech-1.0: the leader's last vertex is (h+0.1) ft inboard of the text point and h/2 below it, so the text point is offset by those amounts (without it the leaders came out 6-12 deg off; verify with COM `GetLeaderLineVertices`: all angles 0/90/180, all lengths 8). The marks must exist: a blocked station is retried on the street side, farther out (11 / 15 ft), tighter, slid up to 20 ft (corner stations up to 60 ft into the run); only a station with no room is omitted and reported. Obstacles: visible survey texts, host labels (incl. `EXIST R/W`), survey lines and DIMENSIONs (short dims block their whole span). `--frame`: a mark touching the sheet frame must be entirely inside it (the viewport cut one to a lone "R"); marks outside it are kept. Labels that merely contain R/W (`EXIST R/W`, `(50' TOTAL R/W)`, `R/W 100.00'`) are information and stay. Seidenstein result: 100 marks, 0 omitted.
* **R/W lines end where the red street lines end** (user 2026-10-26): `node scripts/c300-rw-extend.mjs --dump X-TOPO_dump.txt --config streets.json --out payload.json` extends each surveyed R/W side along the survey centerline to the end station of the red CENTER_LINE, keeping the surveyed offset (half width read from the R-W lines: Ct 25 ft = "50' TOTAL R/W", 74th 20, 76th 50, Ave/Place 20), leaving the crossing street's gap (starts at its far edge) and extending only sides the survey drew. Create the polylines on host layer `R-W` (linetype PHANTOM2, lineweight 40, ByLayer; colour = TRUE COLOR 18,135,139, NOT ACI 4: the xref is displayed faded (XFADECTL 70) so the survey's cyan reads dim teal on screen and a plain ACI 4 layer looks like a different, brighter blue; sample the screen to re-derive it if XFADECTL changes) so they look like the survey's. Where the red line is shorter, extend the red polyline (do not trim survey data). Config example (made-up numbers): `references/standards/streets.example.json`; the real one lives in the project (`_reports/rw-extend-streets.json`). Extensions lie outside the sheet frame; check them in model space (COM `ZoomWindow` + a screen capture).
* **White means white (user 2026-10-26)**: an MLeader's TEXT colour is stored apart from the entity colour (DXF group 90 / 92 in the context data, `-1023410168` = ACI 8, `-1023410169` = ACI 7); setting `.Color = 7` over COM does NOT change it. Fix an existing drawing with `(entmod)` substituting those two codes over every MULTILEADER (run the LISP in the open drawing with `SendCommand`), and create new ones with `colorIndex: 7` (the standard now says 7). ALIGNMENT START/END, EOP, EXIST R/W and the structure labels are all MLeaders. Survey symbols (`SMH`, `mh`, `basin`) keep gray ByLayer entities inside their block definitions, so `topo-white-blocks.mjs --blocks SMH,mh,basin` recolors the definitions (profile `whiteBlocks` now lists the three).
* **Red centerline + street name on every street of the plan** (user 2026-10-26): the build only draws the red CENTER_LINE 250 ft from the near intersection and the names 90 ft either side of it, and the alignment (yellow) stops where the build cut it. When the sheet is extended (or a street leg is bare) run `node scripts/c300-street-names.mjs --config streets.json --dump X-TOPO_dump.txt --host host_texts.json --out payload.json`: red polylines, `TextTopoLabel_ep` names (3 ft, masked, centred on the CL, rotation = CL direction) in the nearest free spot (>= 4 ft from any text, >= 110 ft from the street's other names) and `_cl` symbols 50 ft from the intersection. Seindestein: SW 53RD COURT from the alignment end (4+00) to 250 ft past SW 76TH ST, SW 76TH STREET 250 ft each way (names from the survey STNAMER layer, confirmed on OpenStreetMap for 74th/76th; the survey also names SW 53rd AVENUE at x~893600 and SW 53rd PLACE at x~893018: added in a second pass, user 2026-10-26, with red lines joined to SW 74th / SW 76th at their real intersections (CL lines extended to meet) and 250 ft beyond, names 90 ft either side of each intersection, `_cl` symbols 50 ft out; they lie outside the C-300 frame). SW 76th's centerline is ~13 ft south of the C-300 frame edge, so its line/name exist in the model but not on the sheet.
