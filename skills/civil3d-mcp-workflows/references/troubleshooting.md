# Diagnostics and troubleshooting

Rule: **diagnose before retrying.** Blindly retrying a command that hung only grows the plugin queue.

## Architecture (to know where it fails)
```
Claude --MCP stdio--> Node server (Claude Desktop extension .mcpb)
       --TCP JSON-RPC localhost:8080--> C# plugin inside acad.exe
       --host queue (1 operation at a time)--> Civil 3D API, document thread
```
- Connect timeout `CIVIL3D_CONNECT_TIMEOUT` 5000 ms; command timeout `CIVIL3D_COMMAND_TIMEOUT` 120000 ms; port `CIVIL3D_PORT` 8080.
- Plugin log `%LOCALAPPDATA%\Civil3DMcpPlugin\plugin.log` (or `CIVIL3D_MCP_LOG_DIR`); each request logs `-> method [id]` / `<- method ... durationMs=`.
- Civil 3D command line (typed by the user): `C3DMCPSTATUS` -> `listener running: True/False; pending: N; active: True/False; current: <method>`; `C3DMCPSTART` / `C3DMCPSTOP` start/stop the TCP listener without restarting Civil 3D.

## Automatic diagnosis
`powershell -NoProfile -ExecutionPolicy Bypass -File ~/.claude/skills/civil3d-mcp-workflows/scripts/c3d-health.ps1` checks `acad.exe` (alive, Responding), port 8080, the tail of `plugin.log`, sends `getCivil3DHealth` straight over TCP (no MCP) and compares Claude.exe start time with the deploy time. Direct TCP **answers** but the MCP tool fails -> Node server / extension problem. Direct TCP **silent** -> plugin or Civil 3D problem.

## Known blocking modal dialogs
"Unsigned Executable File" (after every DLL rebuild), xref-not-found notice, "Save changes?", start screen, proxy objects, "Missing SHX", drawing recovery.

**Startup:** `Start-Process "<dwg>"` while Civil 3D is still loading opens `Drawing1.dwg` (empty template) instead of the DWG. Wait for port 8080 (`until (echo > /dev/tcp/127.0.0.1/8080) 2>/dev/null; do sleep 3; done` in Bash, background) and **relaunch** `Start-Process "<dwg>"`: it opens in the existing session and the empty `Drawing1` closes itself (seen 2026-09-26). Close without saving: `close-civil3d.ps1 -Discard '<name fragment>;Drawing1'`. The fase1 engine starts Civil 3D by itself if port 8080 does not answer (and retries the first `newDrawing` once).

**Big orange "i" icons in Model (seen 2026-09-26):** Civil 3D's *label override symbol* (orange circle with "i"): on EVERY label with modified text (those `civil3d_profile_view_apply_annotations` creates with `overrides`: SAN LAT, C.O., WATER SERVICE, ALGN START/END in plan; CROSSING LABEL, MANHOLE in profile). **Not plotted, not in the DWG, not an object** (not in `list_*`, selected together with the label); labels without override (EOP, R/W, plain `C.O`) lack it. Turn off in the Civil 3D session, not in the file: `civil3d_drawing set_system_variable {name:"LABELOVERRIDEGLYPHS", value:0, regen:true}` (or `acad_set_system_variable`; before Claude Desktop loads the new action: `node scripts/plugin-rpc.mjs setSystemVariable '{"name":"LABELOVERRIDEGLYPHS","value":0,"regen":true}'`); by hand: type `LABELOVERRIDEGLYPHS`, Enter, `0`, or commands `AeccHideLabelOverrideGlyphs` / `AeccShowLabelOverrideGlyphs`; also `OPTIONS` -> *AEC Editor* -> *Solution Tips* -> uncheck *Drafting* (turns off all Civil tips). May return to `1` after restarting Civil 3D: reread with `get_system_variable`. **Do NOT** use "Clear Label Text Override" (deletes the text). Delete/close nothing in the DWG for this. Sources: Autodesk Help "Show/Hide Label Override Symbols"; civil3dplus.wordpress.com 2016/08/14.

**The schema loaded by ToolSearch shows required fields as optional** (e.g. `name`/`handle`/`match`, all `z.string().min(1)`): a client-view trim, not the server. For the real schema: run `node build/index.js` over stdio with `CIVIL3D_ENABLE_TOOL_ALIASES=true` and `MCP_HTTP_PORT=3999` (3000 is often taken), do `initialize` + `tools/list`, read `inputSchema.required` (seen 2026-09-27: `acad_get_system_variable` -> `["name"]`). Do not "fix" the TS schema for this.

## Error codes (`CIVIL3D.*` -> JSON-RPC)
`UNAVAILABLE` -32001 · `OBJECT_NOT_FOUND` -32004 · `TIMEOUT` -32008 · `CONFLICT` -32009 · `CANCELLED` -32010 · `INVALID_INPUT` -32602 · `METHOD_NOT_FOUND` -32601 · rest -32000 (`API_ERROR`, `TRANSACTION_FAILED`, `HOST_BUSY`, `NO_DRAWING`, `PATH_NOT_ALLOWED`, `FILE_IO_ERROR`, `COMMAND_FAILED`, `QC_ERROR`, `INTERNAL_ERROR`). Node side classifies messages by regex: /timed out/ -> TIMEOUT; /failed to connect|connection closed/ -> UNAVAILABLE; /not found/ -> OBJECT_NOT_FOUND.

## Protocol on a failure (in order)
0. Suspect a deploy layer (tool missing, field ignored, method not implemented): `node scripts/integrity-check.mjs --only deploy --skip-live` (compares build/extension/DLL/dispatcher and start times) before touching anything.
1. Read the exact message and find it in the table. A new bug: after solving it add the row **and** the entry in `standards/known-bugs.json` (SKILL.md).
2. Run `civil3d_health` (or `c3d-health.ps1` if MCP is silent).
3. Hung operation or no connection: tell the user **what to check on screen** and stop.
4. Retry at most once, only after a change of condition (dialog closed, Civil 3D open, new token).
