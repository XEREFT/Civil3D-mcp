## Engine design decisions (user, 2026-10-01/02, still valid)
- Build a complete Fase 1 **without a guide** from X-TOPO + X-UTIL + X-ARCH (always the 3) + PDFs/scans + Property Appraiser (always). The guide is never a source; in development it is only an exam to measure what is missing.
- Scanned as-builts (TIF) have no copyable text: OCR + location; the scan is not uniformly scaled (never one global transform): fit each baseline with >= 2 STA+N/E anchors; always a review table; only confirmed values enter. **Simulated as-builts are rejected** (`--allow-simulated` only in tests).
- Easement (U.E.): comes from the plat (Clerk site blocks automation: the user downloads once per subdivision) or, when the user has no plat, `pa-area.mjs` proposes shared lot lines, the user confirms line and width -> `project.json site.ue` -> `c300-easement.mjs` (2 DASHED2 polylines +-5 ft, 2 dims 5.00', MLeader "EXIST 5' U.E."). **Never drawn without the user's confirmation.**
- Title block: 7 replacements from `project.json` (`c300-titleblock.mjs`): name, address (formatted `S.W. ... 232ND STREET`), project No., AGR from the POC, sheet = layout, today's date, initials JH; approver CF unchanged. Missing values print placeholders (`XX-XX.XXX`, `XXXXX`, `XXX GPD`) and `fase1-finish` FAILs "pending data" until real values exist (intentional).
- R/W dims: one per survey R/W dim (~25 ft) inside the viewport, at the surveyor's points; short-dim text pulled back to its line (`fase1-fix-dims.mjs`). SAN<->WM separation dims from `asbuilt.json` geometry (`c300-utility-separation.mjs`). Road labels EOP / EXIST R/W / ALIGNMENT START-END from the survey (`c300-road-labels.mjs --native`). PL symbols from county lots or, for tracts, the survey's lot lines (`--survey-lines`). Existing appurtenances (tees, G.V., C.V., plugs, corp stops, CPO, 6" laterals with clean-out) get a MLeader each (`appurtenances` in `asbuilt.json`); scan length is printed on run labels (`337'- EXIST 8" PVC ...`).
- Rules about notes: Fase 1 has no PROP/PROPOSED word except the two standard notes about EXISTING installations (`ALLOWED_PROPOSED_PHRASES` in `fase1PropNotes.ts`); existing networks and their notes are never removed (the designer works on them); the subject label keeps `<use>` and `<GPD>`.
- Survey adaptation (2026-10-25, SEIDENSTEIN): per-surveyor layer roles in `references/standards/survey-profiles.json` + `lib/survey-profile.mjs` (profile picked automatically, or forced by `project.json sources.surveyProfile`); front street by full name (SW 53RD COURT != AVENUE); `sources.streetNames` names an unlabelled street; sheet closes at the near intersection when the block does not fit the viewport; `_cl` imported from X-TOPO or `sources.clFrom`; `sources.xutil:"none"` = project without POC/as-builts.
- MDWASD (county law, 2026-10-02) applies to existing-data cleanup AND design: `standards/mdwasd-standards.json`, `mdwasd-standards.md`, `mdwasd-check.mjs` (inside `fase1-qc.py`), `c300-mdwasd-easement.mjs`, plugin rules `mdwasd_rules.json` + `civil3d_standards_lookup topic=mdwasd`; 660 ft valve check automated.
