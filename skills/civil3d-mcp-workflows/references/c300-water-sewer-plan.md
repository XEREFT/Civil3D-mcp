# C-300 Water & Sewer Plan: recipe from X-TOPO + Property Appraiser

"WATER AND SEWER PLAN" sheet (C-300) + profile (C-301) of FormTech's residential WASD projects. Rules derived from the guide `VILLA ONE @XEREFT\C-300_GUIA_COMO_DEBE_QUEDAR.dwg` (26-04.047) compared with its base `X-TOPO.dwg` and the Goulds project (26-04.046). Project state and open decisions -> project memory. (Current phase is Fase 1 only; folder model in SKILL.md.)

## 0. Inputs: where each datum comes from
| Datum on the sheet | Source | How |
|---|---|---|
| Road geometry, R/W, lots, manhole, FH, fences, BM | `X-TOPO.dwg` (survey) | xref; read with `acad_list_text_entities` / `acad_list_polyline_entities` |
| R/W widths (25.00' CL->R/W dims) | survey dims on layer `DIM` (style `1 IN 20`) | `scripts/dwg-dump.ps1 X-TOPO.dwg` -> `DIM|` lines |
| Folio, P.B./PG, subdivision, lot/block, owner, area | Miami-Dade Property Appraiser | `node scripts/pa-lookup.mjs --xy X,Y` (point inside the lot, drawing coords) |
| House / proposed footprint | `X-ARCH.dwg` (architect) | xref |
| Existing networks (WM, SAN, FH, MH) and refs E#####/ES#### | `X-UTIL.dwg` + WASD as-builts | xref + MLeaders |
| Title, project address, project No., date, drafter | user / proposal | title block (paper space) |

**Address:** vacant lots carry addresses like `227XX` that the PA does **not** geocode. Always search by coordinate (`--xy`); `--address` only if the lot has a real address. The PA centroid is in FL83-EF (EPSG 2236), same as the drawing.

## 1. Delivery structure
- Project folder: `C-300.dwg` + xref DWGs (`X-TOPO.dwg`, `X-ARCH.dwg`, `X-UTIL.dwg`) with a **relative** path (`.\X-*.dwg` same folder, or `.\x-ref\X-*.dwg`; both valid if relative and resolving). Current model: `<NAME> @XEREFT BASE` folder (SKILL.md).
- Xrefs: Overlay, insertion 0,0,0, scale 1, rotation 0; the guide has them on `C-ANNO`, the firm convention is layer `XREF` (`drawing-setup-xrefs-layers.md`): confirm with the user. Coordinate system `FL83-EF`, feet.
- "Clean": no prior-project content in model space, no `(OLD)` layouts, no foreign alignments/pipe runs. Verify with window listings; delete only with user OK.

## 2. Orientation: DVIEW TWist ("the house always faces the street")
The main C-300 viewport is twisted so the **front street is horizontal** and its label reads left to right: `twist_rad = 2*pi - theta_street` (theta = street label rotation / CL angle in that direction). Verified: VILLA ONE theta(SW 118TH AVE)=1.59715 -> twist 4.68603 (268.49 deg); Goulds theta(SW 232 ST)=0.0155 -> 6.26765 (359.1 deg). Viewport 25.0 x 23.0 in, `viewht` 460 -> **1"=20'**, layer `VPORT`.
- Read: `acad_list_viewports { layout:"C-300" }` -> `twistDegrees`, `scaleLabel`, `modelCenterX/Y`. Set: `acad_set_viewport_twist { layout:"C-300", streetAngleDegrees, centerX, centerY }` (center = lot midpoint; token). Equals MSPACE -> DVIEW -> TW.

## 3. Alignments
One centerline alignment of the front street: **a single tangent** in the survey CL direction, from 20 ft past the far intersection to the end of the survey CL, length rounded to 10 ft (guide: 440 ft). Layer `C-ROAD`, name `SW 118TH AVE` (format `SW <n>TH AVE|ST`); `c300-build-spec.mjs` computes it. `civil3d_alignment create` with both CL ends; verify with `station_to_point`. No `Pipe Run - (n)` from earlier projects or alignments from other sites.

## 4. Measuring roads (dimensions)
Aligned dims, style **`BCC-1.0`**, layer **`C-ANNO`**: CL to each R/W line, two per section (e.g. 25.00' + 25.00' = R/W 50'); one section every ~130 ft per street inside the viewport (VILLA: SW 118 Ave 4 sections, SW 227/228 St 2 each). They replicate the survey dims (`DIM`, `1 IN 20`, same points +-1 ft); if the survey lacks one, measure perpendicular to CL up to the R/W line. Easements: dim `5.00'` + MLeader `EXIST 5' U.E.`. Optional (Goulds yes, VILLA no): pavement width `<>\P(EXIST ASPHALT)`, sidewalk `<>\PPROP SIDEWALK`.
Read survey dims: `acad_list_dimensions { layer:"DIM" }` (X-TOPO open) or `dwg-dump.ps1`. Create: `acad_create_aligned_dimension { x1,y1 (CL), x2,y2 (R/W), dimStyle:"BCC-1.0", layer:"C-ANNO", offset }` one per side (token each); extra text `textOverride:"<>\P(EXIST ASPHALT)"`.

## 8. Source rules (dictated by the user 2026-09-25)
- **The base files rule** (survey, as-builts, POC, PA, and the engineer's package `C-300.dwg` + x-ref). The guide/previous sheet was made by a person and can have errors (Goulds folio, RIM 9.63 vs 9.69, FH shifted 12 ft): verify, never copy.

Not Fase 1.
- **Civil plan labels** ("EXIST R/W", "EOP" = AECC_GENERAL_NOTE_LABEL; "ALIGNMENT START/END" = AECC_STATION_OFFSET_LABEL): DXF carries no geometry -> `civil3d_profile_view_annotations` without name returns the package's `planLabels` (NoteLabel with anchor; StationOffsetLabel with alignmentName + location) -> `civil3d_profile_view_apply_annotations` (any view as profileViewName) recreates them with style, layer, override, position. StationOffsetLabel needs a marker ("_No Markers") and a point strictly inside the alignment (use station_to_point). If the template style differs from the package, index-0 override with the package's printed text (e.g. ALIGNMENT START/END with N/E fields `<[Northing(...)]>`/`<[Easting(...)]>`).
- **The guide is only the target (user 2026-09-25): take NOTHING from it** (no coordinates, viewport sizes, objects). `Draft 1.pdf` is a plot of the guide (has its RIM 9.63), not a source either. Provenance audit: `dwg-dump.ps1` of guide and package -> diff by handle; what only the guide has (VILLA: PROP CLF, MH#7 label 9.63, MH7-MH8 0.39% label, 2 arrows, water viewport fix) has no base source -> derive from base data with an explicit rule or ask.
- WASD POC (`POC.pdf`): AGR, GPD water/sewer, description (units, SF), connection point.
- PA page (`gisfs.miamidade.gov/mdarcgis/rest/services/MD_PA_PropertySearch/MapServer/6`, PaParcel, SR 2236 = drawing's): lots and location; compare street angle (must match the twist) and R/W widths. The GIS polygon may differ from the legal description: report, do not adjust silently.
