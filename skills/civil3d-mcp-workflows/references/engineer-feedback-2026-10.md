## 1. LABELS / LEADERS - the main correction (video 2, 00:03:30-00:16:00)

### 1.1 What was wrong in our PROPOSED file
Our earlier session replaced the native Civil 3D plan callouts (`AeccDbStaOffsetLabel`, label style **SAN LAT**, text "PROP 8"x6" SAN LAT CONNECTION / (SEE NOTE ON THIS SHEET) / INV / STA / OFF") with **Multileader copies** (style Formtech-1.0, layer C-ANNO, annotative 1"=20') because COM cannot edit the text of a native label and because of the orange "i" override glyph. The engineer opened our file and said, in substance:
- "In your file that label is not a label any more, it is a **multileader**; if I move it **the numbers never change**; it stays fixed. In mine all the labels are automatic: if I move it, the station updates by itself."
- The leaders that used to meet at ONE point (the lateral/alignment crossing) had been separated: each arrow now sat at a different place instead of all converging to the same point. He could not tell what had been done to them and guessed they were exploded ("that is created with the explode command").
- (He also saw that the angle of some labels/leaders had changed; that one he understood: the user had rotated them while trying to show them horizontal on C-301, and it "looked terrible". Keep the engineer's rotation; do not "fix" it by rotating again.)

### 1.2 The rule (hard)
1. **Every plan callout that carries a station/offset is a NATIVE Civil 3D label bound to the alignment**, never an MLeader/MText: `Annotate > Add Labels > Alignment > Station Offset - Fixed Point`, label style **SAN LAT** (also `C.O`, `WATER SERVICE`, `WATER SERVICE - ASP`, `REMOVE EXIST PLUG`, `ALGN`, `ALGN START`, `ALGN END`, `BEGIN C&G`, `C&G A/B`, `DROP CURB A/B`, `END C&G A/B`, `NEW CURB RAMP A/B` - the template already contains them).
2. STA and OFF come from the label (auto). The **INV line is typed by hand** inside the label (Label text overridden on purpose), it is the only manual part ("the connection text is the same for all, I write it by hand; the invert I fill from the profile").
3. Profile side: **Profile View > Station Elevation** labels (style `Station and Elevation`, marker `_No Markers`) give the elevation automatically; the pipe label is the native **Pipe Profile Label** (pipe label style `Prop San Main`, e.g. "PROP 8" PVC (C-900) SAN MAIN" with the invert via the `End Depth to Invert` property).
4. Moving a native label with its grip moves only the text/leader; the station value follows the arrow position, so **the arrow tip is the control point**. Move the leader TIP and the numbers change; move the text and they do not.
5. The orange circled **"i" = override glyph** is expected on labels with overridden text. The engineer keeps it visible in his own file (seen on screen in both recordings) and never mentioned it as a problem; it is a non-plotting screen marker (verify on our next plot). It is a view problem only (`LABELOVERRIDEGLYPHS`), NOT a reason to replace the label (see section 6 for the conflict with our older rule).
6. Never **explode** or convert a native label to MText/MLeader. If a label is already a Multileader and the numbers must follow the alignment, delete that MLeader and re-create the native label (below) - but only after the user OKs it (suggestion, not an order from the engineer).

### 1.3 How to create ONE native SAN LAT label (video 2, 00:12:00-00:16:00, frames 735-920 s)
1. Make sure the lateral crossing point is known in plan (the lateral line meets the street alignment at offset 5.00' L).
2. `Annotate > Add Labels` -> dialog "Add Labels": Feature = **Alignment**, Label type = **Station Offset - Fixed Point**, Station offset label style = **SAN LAT**, Marker style = `<none>` -> Add.
3. Command line: pick the alignment, then pick the point (use endpoint/intersection snap on the lateral). The label prints `INV: '` (empty) + `STA: x+xx.xx/OFF: 5.00' L`.
4. Move the text with its grip to clear space (leader follows the tip). Because the tip stays on the lateral, STA/OFF stay right.
5. Fill the invert: read it from the profile (the Station Elevation label at the same station, see 1.4) -> select the label -> contextual tab **Edit Label Text** (`EditLabelText`) -> `Text Component Editor - Label Text`, type the value after `INV: ` -> OK. `Reset Label` brings the style text back; `Toggle Label Pin` pins it.
6. If the label must be re-attached to a different station (design change): drag the tip to the new point, then in `Properties` the station follows; edit INV again.

### 1.4 Invert workflow between plan and profile (video 1, 00:09:00-00:11:40, video 2, 00:13:00-00:16:30)
- Plan label gives the station (and offset, e.g. STA 1+74.67 / OFF 4.34' L). In the main profile view find that **same station**, draw a vertical line up from it to the pipe in the profile, put a **Station Elevation** label where it hits the pipe (that is the invert, e.g. -3.70) and copy that number into the plan callout's INV line. "This one gives me the horizontal (plan station), this one gives me the vertical (profile elevation); in the end both must agree." The profile label is automatic: if you move the pipe/alignment, the elevation updates by itself and only the typed INV in the plan has to be re-edited.
- The street alignment has **no 3D data** (elevation property) so Civil 3D cannot give the invert in the plan label automatically: that is why INV is manual. "Everything is connected, but trying to make everything automatic costs more time: knowing WHAT is automatic with a clear plan was done in 5 minutes."
- Example the engineer gave: invert changed 2.87 -> 2.75 by moving the point, then re-edit the INV text in each label; 4 lateral profiles in 20 minutes manually vs 1.5-2 h fully automatic.
- **Crossing point label**: there is no automatic label option for the crossing point of another pipe; he does that one manually.

### 1.5 Lateral table
The lateral schedule table is a Civil 3D table linked to those alignment labels/alignments (needs an object with properties). So: **never delete the (yellow) notes/labels the table reads**; turn their layer to **no-plot / off** so they do not print. The user's attempt to build the laterals as Pipe Network pipes failed the table ("the table needs a physical object with properties") - the engineer builds laterals as alignments + 2D profile lines.

## 2. Viewports, scale, layers (video 2, 00:06:40-00:10:30)

## 3. Design method (video 1) - rules for every sewer-extension PROPOSED
Context: Seidenstein, 9 ASP (Additional Services Program) laterals + the 10th (subject lot), 8" gravity main in SW 53 Ct to the NW corner of the subject property.
- **Fase 1 review**: keep trees, pavement/asphalt, driveways and structures ("we need to know where trees and asphalt are"); remove only textures/hatches, keep the lettering; do not over-clean the topo; put topo info on NO PLOT layers instead of deleting; draw existing storm lines when the survey has the data (we could have).
- **Alignment direction**: always LEFT to RIGHT ("one always starts left to right"); start station 0+00 where it suits the 1"=20' window (he moved the user's alignment start to the corner); the user's choice was fine, he only showed his.
- **Laterals**: one per ASP folio (POC page 4 table; circles mark the 9 houses). Route through **green areas (grass)**, away from trees, pavers and driveways ("driveways are expensive; do not make them break them"); pick an ideal point on the grass at a "nice" distance from the property (he chose 30 ft; lateral lengths printed are 20-30 LF). Lateral size/slope identical every time: 6" PVC (C-900) @ 1.04%. A structure (manhole) at least every 300 ft; where a straight run conflicts with an existing structure, offset and return.
- **Three labels per lateral, always the same three**: (a) `PROP 6" C.O. AND 6" CAP / (SEE NOTE ON THIS SHEET) / (ASP FOR <folio>)`; (b) `PROP <n> LF OF 6" PVC (C-900) / SAN LAT @ 1.04% SLOPE / (PER SS 1.0 SHT 2 OF 2) [/ (SEE SAN LAT PROF n)]`; (c) the native SAN LAT connection label (section 1) with INV/STA/OFF. The circle is the C.O.
- **Lateral profile views**: a 50 ft line from corner to corner across the street (-25 to +25 about the centreline), alignment `SAN LAT n`, profile `SAN LAT n`, view style grid V:10, surface-sampled existing ground, ground set 0 at the centre ("zero at the middle"). Draw the existing utilities, then the proposed lateral by hand in 2D: **30" minimum cover at the C.O. end**, 12" minimum, deep laterals go down to a chosen depth and rise quickly (deep profile shape is always the same), shallow ones run straight. Copy the first profile for the others and adjust (all laterals share 1.04%).
- **Inverts**: check each one (e.g. 4.10 -> 3.56 -> 3.16); main at 0.4% in the engineer's file (our approved 0.5% decision stays ours, see memory `design-phase-rules-seidenstein`).
- **Drafting speed**: do not rebuild what exists ("why reinvent the wheel"); copy/paste the profile pieces; commands he uses: `BR` (break), `F` `R` `0` (fillet radius 0 to join lines), SPACE as Enter; "start from numbers already set - it helps thinking".
- **Sheet set to deliver**: C-001 cover, C-300 plan, C-301 profiles (5 profiles: main + 4 lateral views) = 3 sheets, PDFs of the three.
- **Standards source**: the county/MDWASD standards ("Those are the standards"); the user must always check the standards before drawing.
- **Process**: the engineer wants the user to send screenshots/doubts any time; will return the finished file to compare; wants label styles cleaned (many unused) and renamed, organised (lateral first, then water main...), fewer styles, hide what is not used.
